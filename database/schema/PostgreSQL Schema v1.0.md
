# PostgreSQL Schema v1.0

# Stato Documento

Documento di progettazione dello schema PostgreSQL di CollectorVerse.

Questo documento traduce il CollectorVerse ERD v1.0 in una struttura dati implementabile mediante PostgreSQL e Supabase.

---

# Obiettivo

Definire:

- Tabelle
- Colonne
- Primary Key
- Foreign Key
- Vincoli
- Indici
- Relazioni

necessari per l'implementazione della piattaforma.

---

# Convenzioni

## Naming

Tutte le tabelle utilizzano:

- minuscolo
- snake_case
- nomi plurali

Esempi:

users
user_profiles
marketplace_listings
wishlist_items

---

## Chiavi Primarie

Tutte le tabelle utilizzano:

uuid

come Primary Key.

Formato:

id UUID PRIMARY KEY

---

## Timestamp Standard

Quando applicabile, tutte le tabelle utilizzano:

created_at
updated_at

---

## Soft Delete

Quando applicabile, le eliminazioni utilizzano:

deleted_at

invece della cancellazione fisica.

# Tabella: user_roles

## Scopo

Definisce i ruoli disponibili all'interno della piattaforma.

La tabella permette l'estensione futura dei ruoli senza modifiche strutturali al database.

---

## Nome Tabella

user_roles

---

## Primary Key

id UUID PRIMARY KEY

---

## Colonne

| Colonna | Tipo | Obbligatorio | Descrizione |
|----------|----------|----------|----------|
| id | UUID | SI | Identificativo univoco |
| code | VARCHAR(50) | SI | Codice interno ruolo |
| name | VARCHAR(100) | SI | Nome visualizzato |
| description | TEXT | NO | Descrizione del ruolo |
| is_active | BOOLEAN | SI | Ruolo attivo |
| created_at | TIMESTAMP | SI | Data creazione |
| updated_at | TIMESTAMP | SI | Data ultima modifica |

---

## Valori Iniziali

| Code | Name |
|--------|--------|
| user | Utente |
| moderator | Moderatore |
| admin | Amministratore |

---

## Relazioni

user_roles (1)
↓
(N)
users

---

## Vincoli

code deve essere univoco.

name deve essere univoco.

---

## Indici

PRIMARY KEY (id)

UNIQUE (code)

UNIQUE (name)

---

# Tabella: users

## Scopo

Rappresenta tutti gli account registrati nella piattaforma CollectorVerse.

Ogni utente autenticato possiede una sola registrazione nella tabella users.

---

## Tipo Tabella

Principale

---

## Primary Key

id

Tipo:

UUID

---

## Colonne

### id

Identificatore univoco dell'utente.

Tipo:

UUID

---

### email

Indirizzo email utilizzato per l'accesso.

Tipo:

TEXT

---

### username

Nome utente univoco.

Tipo:

TEXT

---

### role_id

Ruolo associato all'utente.

Riferimento:

user_roles

Tipo:

UUID

---

### is_active

Indica se l'account è attivo.

Tipo:

BOOLEAN

Valore predefinito:

TRUE

---

### is_email_verified

Indica se l'email è stata verificata.

Tipo:

BOOLEAN

Valore predefinito:

FALSE

---

### active_profile_frame_id

Cornice profilo attualmente utilizzata.

Tipo:

UUID

Obbligatorio:

NO

---

### current_level_id

Livello attualmente raggiunto.

Tipo:

UUID

Obbligatorio:

NO

---

### created_at

Data creazione account.

Tipo:

TIMESTAMP

---

### updated_at

Data ultimo aggiornamento.

Tipo:

TIMESTAMP

---

### deleted_at

Data eliminazione logica.

Tipo:

TIMESTAMP

Obbligatorio:

NO

---

## Foreign Keys

role_id
→ user_roles.id

active_profile_frame_id
→ profile_frames.id

current_level_id
→ level_definitions.id

---

## Indici Previsti

email

username

role_id

---

## Note Architetturali

La tabella users rappresenta esclusivamente l'account.

Le informazioni pubbliche dell'utente vengono memorizzate nella tabella user_profiles.
