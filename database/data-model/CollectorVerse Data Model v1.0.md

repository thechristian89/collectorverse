# CollectorVerse Data Model v1.0

# Stato Documento

Questo documento definisce il modello concettuale dei dati di CollectorVerse.

Il Data Model rappresenta la traduzione del Blueprint e delle Business Rules in entità logiche che saranno successivamente utilizzate per la progettazione di:

- Entity Relationship Diagram (ERD)
- Database PostgreSQL
- Schema Supabase
- API
- Frontend
- Mobile App

---

# Obiettivo

L'obiettivo di questo documento è identificare tutte le entità che devono essere memorizzate dalla piattaforma e descrivere le relazioni principali tra esse.

Questo documento non definisce:

- tabelle database
- colonne
- tipi di dato
- query SQL
- policy di sicurezza

Tali elementi saranno definiti nelle fasi successive.

---

# Struttura del Data Model

Il Data Model è suddiviso nelle seguenti aree:

1. Core Identity
2. Catalogo Universale
3. Catalogazione Personale
4. Marketplace
5. Matching
6. Catalogo Collaborativo
7. Scansioni
8. Gamification
9. Notifiche
10. Amministrazione
11. Importazione ed Esportazione

---

# Parte 1 - Core Identity

# Scopo

Questa sezione definisce le entità fondamentali relative a:

- utenti
- profili
- ruoli
- piani
- impostazioni
- privacy
- comunicazioni
- recensioni
- commercianti

Tutte le funzionalità della piattaforma dipendono direttamente o indirettamente da queste entità.

---

# Entità: User

## Scopo

Rappresenta un account registrato nella piattaforma.

## Utilizzo

User identifica univocamente una persona che utilizza CollectorVerse.

Ogni account registrato deve possedere una singola entità User.

## Relazioni Principali

User può possedere:

- un Profilo Utente
- un Piano
- un Ruolo
- impostazioni Privacy
- impostazioni Notifiche
- Collezioni Personali
- Wishlist
- Annunci Marketplace
- Conversazioni
- Badge
- Attività Gamification

---

# Entità: UserProfile

Categoria
↓
Collezione
↓
Serie
↓
Oggetto
↓
Versione
↓
Variante

# Entità: Item

## Scopo

Rappresenta l'oggetto collezionabile principale.

## Esempio

Series:
Set Base

Item:
Charizard 4/102

## Relazioni Principali

Item appartiene ad una Series.

Item può possedere molte ItemVersion.

Item può possedere molte ItemVariant.

Item può possedere molte CatalogImage.

---

# Entità: ItemVersion

## Scopo

Rappresenta una diversa edizione dello stesso Item.

## Esempi

Item:
Charizard 4/102

Versioni:

- Italiano
- Inglese
- Giapponese
- Tedesco

## Regole Fondamentali

Le Versioni non rappresentano nuovi Item.

Le Versioni non aumentano il completamento delle Collezioni.

## Relazioni Principali

ItemVersion appartiene ad un Item.

---

# Entità: ItemVariant

## Scopo

Rappresenta una variante produttiva di un Item.

## Esempi

- errore di stampa
- errore di colore
- errore di centratura
- errore di conio

## Regole Fondamentali

Le Varianti non rappresentano nuovi Item.

Le Varianti non rappresentano nuove Versioni.

Le Varianti non aumentano il completamento delle Collezioni.

## Relazioni Principali

ItemVariant appartiene ad un Item.

# Entità: CatalogImage

- immagini candidate

- immagini archiviate

## Relazioni Principali

CatalogImage può appartenere a:

- Item
- ItemVersion
- ItemVariant

## Scopo

- correzioni
